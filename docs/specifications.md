# SKK-JISYO.mahjong-riichi の仕様

この文書は、その時点の仕様の全体を書く。main では常に最新に保つ。

v0.0.2 までの決定は ADR を経ずに直接この文書（当時は `docs/design.md` と `docs/criteria.md`）に書いていた。
それ以後の仕様の変更は ADR（`docs/adr/`）で決め、同じ変更でこの文書と `README.md` も直す。
ADR の運用は [ADR 0001](adr/0001-adopt-adr-and-adr-guard.md) による。

語の追加・削除は、この文書の収録基準に従う限り仕様の変更ではないので、ADR は要らない。収録基準そのものを変える場合は ADR を書く。

## 収録基準

### 収録する語

次の **いずれか** を満たす語を収録する（OR 条件）。
AND にすると「喰いタン」のような、派生語だが外部の用語集に見出しがあり、意味も部分から予測できない語が落ちる。

| basis | 条件 | 例 |
|---|---|---|
| 1 | 生産的な接辞による派生でない基底語 | 聴牌、刻子、嶺上開花 |
| 2 | 派生語でも、外部の用語集で見出しになっている | 全ツ（Wikipedia「麻雀用語一覧」の見出し「ゼンツ」） |
| 3 | 派生語でも、意味が部分から予測できない | 喰いタン、全ツッパ、押し引き |

`data/*.tsv` の `basis` 列に、満たす条件の番号を書く（複数可）。

外部の用語集として、現時点では次を使う。

- Wikipedia「麻雀用語一覧」「麻雀の役一覧」「麻雀のローカル役」（`data/index/wikipedia.tsv`）
- 麻雀のすべて「麻雀用語辞典」（mjall.jp）の見出し
- 天鳳のマニュアルと Mリーグ公式の成績項目の一覧（和了率、放銃率、ラス回避率 など。-率 は生産的な接辞だが、
  成績項目として定義されている語は用語集の見出しとみなす）
- Mozc OSS 辞書（`dictionary_oss`）に麻雀の表記として載っていること（表記の裏付けとして）

### 収録しない語

- 生産的な接辞（-マン、-気味、-打ち、-系 など）による派生語で、上の条件に当たらないもの。例: 全ツマン
- 個人の遊びの読み。例: りっちょく（立直）
- 中国麻雀のルール内の用語（別辞書の予定）。ただし麻雀の種類を指す語（三麻、四麻、中国麻雀、台湾麻雀など）は本体に入れる
- 一般語と同じ読み・同じ表記で、麻雀に固有の表記を持たない語。例: かべ /壁/、すじ /筋/、かも /鴨/、
  なく /鳴く/、しぼる /絞る/、みのがす /見逃す/、じょうけん /条件/、きたいち /期待値/、ぶらふ /ブラフ/
  これらは SKK-JISYO.L などの一般の辞書で変換できるので、`[麻雀]` を付けて重ねる意味が薄い。
- 個人名（プロ雀士の名前）

固有名詞（サービス名・卓・段位・団体・タイトル戦・作品名）とカタカナだけの語は収録する（「設計」の「カタカナだけの語」「固有名詞」）。
固有名詞は、サービス名つきの形（天鳳特上卓）と、実際に使われている省略形（特上卓、特上）の両方を収録する。
サービス名つきの形は直結した用例が見つからなくても、構成要素それぞれに出典があれば収録する。

### 当て読み

略した読みに正式表記を当てる組（ほんいつ→混一色）も同じ基準で判定する。

- 前例: Mozc の ちんいつ→清一色、じゅんちゃん→純全帯么九
- Wikipedia「麻雀の役一覧」の略称欄にある略称の読みには、その行の役名を当てる（basis 2）。
  例: いっつー→一気通貫、ちゃんた→混全帯么九、りゃんぺー→二盃口
- **めんぜん→門前清自摸和は収録しない**。「麻雀の役一覧」で門前清自摸和の略称は「ツモ」であり、
  「メンゼン」を門前清自摸和の略称とする外部の用語集を確認できなかった（Mozc も めんぜん→門前 のみ）。
  代わりに つも→門前清自摸和 を収録した（略称欄と Mozc の両方にある）。

### 出典

すべての (読み, 候補) の組に出典が要る。`scripts/build.ts`（`deno task build`）は出典のない組があると失敗する。

出典は次の順で自動照合し、取れない場合は `data/refs.tsv` に出典を足して `refs` 列で参照する。

1. skk-dev/dict の SKK-JISYO.L / SKK-JISYO.requested / SKK-JISYO.JIS3_4（[麻雀] 注釈付きの語は自動で取り込む）
2. Wikipedia 索引（`data/index/wikipedia.tsv`）
3. Mozc OSS 辞書
4. Wikipedia「Category:麻雀」配下の記事をコーパスにしたカタカナ語の出現数（`data/index/corpus.tsv`）。
   カタカナだけの候補で、読みが表記と一致し、3 回以上出ているもの

組ごとの出典は生成物の `provenance.tsv` にある。`via:` で始まる出典は、長音の機械展開（「設計」の「長音」）で
生じた読みが、展開元の読みから引き継いだものを表す。

### メンテナの判断で収録した語

外部の出典が見つからない、または個人の出典しかないが、頻出するとメンテナが判断して収録した語。
`data/refs.tsv` の `maintainer` を出典に付けて区別する。

| 語 | 補足 |
|---|---|
| ちゅんま /中麻/ | 読み「ちゅんま」は Wikipedia「中国麻雀」にある。「中麻」という表記の出典は見つかっていない |
| ごぶろっく /5ブロック/５ブロック/ | 出典は個人の戦術ノート（Scrapbox）だけ |
| てんぱいはずし /テンパイ外し/ | 同上 |
| ぱいし /牌姿/ | 確認できた読みは「はいし」（Wikipedia「麻雀用語一覧」）だけ。メンテナがふだん「ぱいし」と読んでいるため収録 |

### 保留中の語（出典が見つかるまで入れない）

| 語 | 理由 |
|---|---|
| てんぱr /聴牌/（聴牌る） | 「テンパる」は確認できた（てんぱr /テンパ/ は収録）。漢字表記「聴牌る」の用例は確認できていない |
| 萬子の「〜まん」読み（いーまん→一萬 など） | Mozc にあるのは「〜わん」読み（と さんまん）だけだった |
| しゃーば /西場/ | 読み「しゃーば」の出典を確認できていない |
| 中張牌の ちゅーちゃんぱい、端牌の はしぱい・たんぱい | 確認できたのは ちゅんちゃんぱい・ちゅうちゃんぱい（JMdict）、はしはい だけ |
| 雀魂の 玉の間・雀傑・魂天 | 表記は確認したが、読みを書いた信頼できる出典が見つかっていない（雀豪 は Wikipedia「麻雀用語一覧」にある） |
| 雀王・雀竜位・女流雀王・令昭位 | 同上 |
| 天鳳のスラング（鳳凰民、鳳南、特南、特東） | 使用例のページを確認できていない |
| 平着、ラス率、マンガン・ハネマン・バイマン（カタカナ表記） | 読みまたはカタカナ表記での使用を確認できていない |

### 基準の見直し

派生語の追加要望の issue が大量に来たら、この基準を改める。

## 設計

### 長音

中国語由来の音で読む語（`data/*.tsv` の flags に `lv`）は、「う・い」の形と「ー」の形の両方の読みを立てる。
日本語の音読みの語（三色同順、一気通貫、門前など）は「う・い」の形だけにする。

展開は機械的に行う（`scripts/lib.ts` の `toLong` / `toKana`）。

- 「ー」の形: お段・う段の直後の「う」と、え段の直後の「い」を「ー」にする（ほうてい→ほーてー）
- 「う・い」の形: お段・う段の直後の「ー」を「う」に、え段の直後の「ー」を「い」にする
  あ段・い段の直後の「ー」と、「うー」（五）の「ー」は残す（まーじゃん、ちーといつ、うーぴん）
- 展開するのは「全部う・い」「全部ー」の 2 通りと、データに書いた形だけ。混在形を全部は作らない
  （ちゅうれんぽうとう は 8 通りではなく 3 通り以内）

長音は重複判定より先に決める必要がある。SKK-JISYO.L には「はいてい」「はいてー」のように両方の形があり、
片方しか持たない語もあるため、展開した後の読みで L と照合する。

### 重複の単位

重複除去版（`.L-unique`）は、SKK-JISYO.L と **(読み, 候補) の組** が一致する候補だけを除く。
注釈は比較しない。見出し単位で除くと、L に「はいてい」がある時点で 海底摸月 なども消えてしまう。

### 重複除去版が比較した L の記録

- 比較した skk-dev/dict のコミットは `sources.lock` に固定する
- 生成した `.L-unique` のヘッダーに、そのコミットハッシュ全体を書く
- `provenance.tsv` の `in_L` 列に、組ごとの L での有無を書く

### 文字コード

UTF-8 だけを配布する。EUC-JP 版は作らない。

- 麻雀用語には JIS X 0208 にない字（么、碰）が多く、EUC-JP 版ではそれらの候補を落とすか異体字に置き換えるしかないため
- 原データのうち SKK-JISYO.JIS3_4 は EUC-JIS-2004 で、WHATWG の euc-jp デコーダ（Deno の TextDecoder）では
  JIS X 0213 固有の字が別の字に化ける。`[麻雀]` 注釈の行だけを `decodeEucJis2004()` で読み、
  0213 固有の字は `JIS2004_EXTRA` に書いた対応表（今は 么・碰）で読む。表にない字があれば生成を止める

### 注釈

すべての候補に `[麻雀]` を付ける。説明文は書かない。skk-dev/dict から取り込んだ語の説明
（「七対子の略」など）も落とす。

標準の役名（`data/mahjong.tsv` の flags に `yaku`）のうち、SKK-JISYO.L に (読み, 候補) の組がないものには
`[麻雀][requested]` を付ける。upstream（skk-dev/dict）へ送る候補の目印にする。

- 標準の役名は、Wikipedia「麻雀の役一覧」の「主な役」にある漢字の役名（人和を含む）と、その備考欄の別名（海底撈月、
  十三么九、四喜和）、異体表記（槍槓）とする
- ローカル役（三連刻、大車輪 など）、略称（一通、七対、清一 など）、カタカナ表記（タンヤオ など）、
  途中流局の名前（九種九牌 など）には付けない
- 判定は候補単位で行う。skk-dev/dict の SKK-JISYO.requested から取り込んだ組（さんあんこ /三暗刻/ など）も、
  L になければ `[requested]` が付く
- 么・碰 を含む候補は L（EUC-JP）には入らないので、送るなら SKK-JISYO.JIS3_4 などが対象になる

### 送りありの語

SKK-JISYO.L にない次の語を入れる。

- あがr /和了/アガ/（和了る・アガる）
- つもr /自摸/ツモ/（自摸る・ツモる）
- てんぱr /テンパ/（テンパる）。漢字の「聴牌る」は保留（「収録基準」の「保留中の語」）
- おりr /オリ/（オリる）

サ変動詞（ポンする、ロンする）は名詞だけを収録する。SKK では「ポン」と「する」を分けて変換できるため。

### 数値変換

L の `#ほんば /#3本場/` にそろえて `#3` を使う。

- `#まん` `#わん` → `#3萬`（萬子は「マンズ/ワンズ」と読む。#まん にも萬を足す）
- `#ぴん` → `#3筒`
- `#そう` `#そー` → `#3索`

### カタカナだけの語

入れる（ポン、チー、ベタオリ、ノベタン など）。

- 麻雀用語にはカタカナで書くのが普通で、漢字に変換しにくい語が多い。かな漢字変換の流れのまま確定できるようにする
- 漢字表記もある語（リーチ/立直、テンパイ/聴牌）は両方を候補にする。並びは、麻雀の文脈でより多く使われている表記を先にする
- カタカナだけの候補は読みが表記から決まるので、Wikipedia の麻雀記事コーパス（`data/index/corpus.tsv`）で
  3 回以上出ていれば出典として扱う

### 固有名詞

本体に含める（使う頻度が高いため）。

- サービス名・卓・段位・団体・タイトル戦・作品名など
- サービス名つきの形と、実際に使われている省略形の両方を見出しにする。
  例: てんほうとくじょうたく /天鳳特上卓/、とくじょうたく /特上卓/、とくじょう /特上/
- 個人名（プロ雀士の名前）は入れない

### 候補の並び順

- 本辞書は一般の意味の候補を持たない。一般の意味は併用する L などが担う。SKK で L より後に本辞書を
  読ませれば「一般の意味が先、麻雀の意味が後」になる
- 同じ読みの中では、よく使われる表記・正式な表記を先に置く。実装上は `data/mahjong.tsv` に書いた順、
  その後に skk-dev/dict から取り込んだ順

### リリースノート

[ADR 0002](adr/0002-categorized-release-notes.md) による。`v` で始まるタグを push すると、`.github/workflows/release.yml` が
`scripts/release_notes.ts` で生成し、GitHub の Releases に置く。

- 日本語で書く。この辞書を使うのは日本語話者だけなので、リリースノートを英語で書くという利用者の規則の例外とする。コミットの件名は英語のまま載せる
- 節は「追加」「変更」「削除」「修正」「語彙」「配布物」の順。中身のない節は書かない（「語彙」と「配布物」は常に書く）
- 冒頭は前のリリースへの絶対リンクを含む「… からの変更。」。前のリリースがなければ「初回リリース。」
- 前のリリースは、GitHub Releases の一覧で今回のタグを除いた最新のもの。そのタグから今回のタグまでの、マージを除くコミットを件名の最初の単語で分ける

  | 最初の単語（大文字小文字は区別しない） | 節 |
  |---|---|
  | `Add`、`Introduce`、`Create`、`Support` | 追加 |
  | `Remove`、`Delete`、`Drop` | 削除 |
  | `Fix`、`Correct` | 修正 |
  | それ以外 | 変更 |

- 件名が版番号だけのコミット（`v0.0.2` など）は載せない
- 各行には短い SHA でコミットへの絶対リンクを付ける。件名の `(#123)` は PR への、`ADR NNNN` はそのタグ時点の ADR のファイルへの絶対リンクにする
- 「語彙」には、前のリリースの完全版と比べた (読み, 候補) の組の追加・削除・注釈の変更の数と一覧（`<details>` で畳む）を載せる
